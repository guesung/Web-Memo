# 자율 모드 — gs 파이프라인이 사람에게 묻는 자리

`/gs:` 파이프라인은 **자율 모드로 돈다.** 설계가 확정되면 그 뒤로는 구현·QA·테섭 배포·PR까지 멈추지 않는다. 설계를 확정하는 입구는 둘이다.

- **AI 경로** (`/gs:idea` → `/gs:design`) — AI가 기획·설계를 다 정하고, 마지막에 **설계를 사람에게 설명해** 한 번 승인을 받는다.
- **같이 정하는 경로** (`/gs:discuss`) — 사람과 결정 지점을 하나씩 합의하며 기획·설계를 쓰고, 완성된 설계를 설명해 확정을 받는다.

이 파일이 "어디서 묻고 어디서 안 묻는가"의 SSOT다. 각 스킬은 여기를 따르고 자기 파일에서 다시 정하지 않는다.

```
작업 지시 → [/gs:idea 자동] → [/gs:design 자동] → 설계 설명 → ★ 승인 ──┐
                                                                          ├─ 입구마다 게이트 하나
작업 지시 → [/gs:discuss  사람과 같이 기획·설계] → 설계 설명 → ★ 확정 ──┘
                                                        │
                                                        ▼
              /gs:implement → 셀프 QA → 테섭 배포(develop 머지) → PR → 보고
                              ───────── 여기부터 보고까지 묻지 않는다 (보고 뒤 /gs:problem-log 승인만 예외)
```

## 묻는 자리는 입구마다 하나다

| | 자리 | 왜 남겼나 |
|---|---|---|
| ★ | [`/gs:design` ⑥ 설계 설명 → 승인](skills/design/SKILL.md) | 이 뒤로는 코드·커밋·PR이 전부 자동으로 나간다. 되돌리는 비용이 가장 큰 마지막 지점이고, 승인 한 번으로 그 뒤 전부를 위임하는 계약이다 |
| ★ | [`/gs:discuss` ③ 설계 설명 → 확정](skills/discuss/SKILL.md) | 같은 계약을 사람과 같이 정한 설계로 맺는다. 이 경로는 확정 전까지 결정 지점마다 사람에게 묻는다 |

**게이트에서는 결정 목록이 아니라 설계를 설명한다.** 형식은 [`/gs:design`](skills/design/SKILL.md) ⑥이 SSOT다. 사람이 승인하는 건 설계이고, AI가 정한 것은 그 설계 안의 자리에서 이유와 함께 읽혀야 판단할 수 있다.

**AI 경로와 구현 이후에서는 그 외 어디서도 `AskUserQuestion`을 부르지 않는다.** 예전에 묻던 자리(레포 선택 · 정체/아키텍처/디자인 시스템 문서 인터뷰 · 기획 승인 · 막힌 지점 · 논의 필요 확인)는 전부 아래 §자동 결정으로 처리한다.

예외는 아래와 같다.

- **orca 메모에 작업카드가 없을 때**: 노션 URL 없이 시작한 `/gs:implement`·`/gs:implement-loop`가 새 카드를 만들지 묻는다. 규칙은 [orca-worktree.md](orca-worktree.md#카드-없음-확인)가 SSOT다. orca 밖이면 묻지 않고, `카드 없이 진행`을 골라도 그대로 돈다.
- **master 대상 PR에서 작업 카드를 모를 때**: [`/gs:pr`](skills/pr/SKILL.md)이 카드를 묻는다. 카드 없이 master로 PR을 올리지 않는다. 파이프라인 안에서도 마찬가지다.
- **`/gs:problem-log`는 언제나 승인을 받는다.** 단독이든 작업 스킬(`/gs:implement-loop`·`/gs:implement`·`/gs:issue-solve`·`/gs:self-qa`)이 끝에서 부르든 같다 — 점검 규칙은 [problem-log](skills/problem-log/SKILL.md#작업-스킬-끝의-점검)가 SSOT다. 작업 스킬은 PR·마지막 출력까지 다 낸 **뒤에** 점검하므로 파이프라인을 멈추지 않는다. 틀린 원인이 조용히 쌓이는 비용이 한 번 묻는 비용보다 크다.
- **사람이 `/gs:interview`를 직접 부른 경우**다. 묻는 것이 존재 이유라 단독 호출에서는 기존대로 묻는다.
- **`/gs:discuss`** 는 사람과 같이 기획·설계를 정하는 입구다. 확정 전까지 결정 지점을 하나씩 사람에게 묻고 합의된 것만 쓰며, 자동 결정을 쓰지 않는다(되돌리는 비용 `낮음` 세부만 추천값을 넣고 설계 설명에 드러낸다). 확정 뒤로는 AI 경로와 똑같이 묻지 않는다.

## 자동 결정 — 묻지 않는 대신 남긴다

묻고 싶은 지점에 걸리면 **멈추지 않고** 이 순서로 처리한다.

1. **조사한다.** 맥락 → 레포 → 프로젝트 문서(`docs/project-identity.md`·`docs/architecture.md`·`docs/design-system.md`·`CLAUDE.md`) → 공식 문서. 답이 나오면 그건 결정이 아니라 확인이다.
2. **그래도 갈리면 가장 보수적인 쪽을 고른다.** 보수적 = 되돌리는 비용이 작은 쪽 · 기존 동작을 덜 바꾸는 쪽 · 범위를 덜 넓히는 쪽.
3. **기록한다.** 노션 모드는 페이지 `## 논의 필요`, 파일·지시 모드는 상태 파일 `open_questions`에 아래 형식으로.

```
[AI 자동 결정] <무엇을 정했나> — <선택지> / 채택: <고른 것> / 근거: <왜> / 되돌리는 비용: 높음|중간|낮음
```

4. **최종 보고에 편다.** §보고 의무 참조.

**가정을 숨기지 않는다.** 안 물어본 것이 판단인지 누락인지 사람이 구별할 수 있어야 자율 모드가 성립한다.

## 권한·시크릿이 필요할 때 — 묻지 말고 직접 한다

로그인·토큰·대시보드 확인·배포 상태처럼 **권한이나 시크릿이 걸린 일도 사람에게 떠넘기지 않는다.** 붙어 있는 MCP·스킬로 직접 해결한다.

| 필요한 것 | 먼저 쓰는 것 |
|---|---|
| 로그인된 웹 서비스 확인·조작 (대시보드 · 콘솔 · 관리자 화면) | `aside-browser` 스킬 — 사용자의 로그인 세션·브라우징 맥락을 그대로 쓴다 |
| 로그인이 필요 없는 브라우저 조작 · QA 판정 | `playwright` MCP |
| 배포 상태 · 배포 URL · 빌드 로그 · 런타임 에러 | `vercel` MCP (`get_deployment`, `list_deployments`, `get_deployment_build_logs`) |
| 환경변수 값 | 레포의 `.env*` 파일을 로컬에서 직접 읽는다. 값을 에이전트 프롬프트나 노션·PR 본문에 옮기지 않는다 |
| 노션 페이지·DB | `notion-home` MCP (개인 DB) |
| GitHub PR·이슈 | `gh` CLI |

원칙 셋:

1. **먼저 시도한다.** "권한이 필요할 것 같다"는 짐작으로 사람에게 되묻지 않는다. 실제로 호출해 보고 막히는지 확인한다.
2. **막히면 대체 경로를 하나 더 시도한다.** 예: `vercel` MCP가 안 되면 `aside-browser`로 대시보드를 직접 본다.
3. **둘 다 막히면 그때만 사람에게 알린다.** 질문이 아니라 **보고**다 — 무엇을 시도했고 어떤 에러로 막혔는지 최종 보고에 한 줄로 남기고, 그 항목만 건너뛴 채 나머지를 끝낸다.

**시크릿 값 자체는 어디에도 옮겨 적지 않는다.** 키 이름까지만 넘기고 값은 실행 지점에서 로컬로 읽는다 — 노션 페이지·PR 본문·에이전트 프롬프트·최종 보고 전부 해당한다.

## 그래도 멈추는 것 — 질문이 아니라 정지

아래는 "물어볼까?"가 아니라 **작업을 더 진행하면 안 되는 상태**다. 자율 모드여도 그대로 멈춘다.

| 조건 | 왜 |
|---|---|
| 대상 레포가 `레포지토리/cashwalk/` 아래 | 회사 코드를 품질 판정 없이 PR까지 보내는 사고를 막는 가드레일 |
| 타입체크·빌드 2회 연속 실패 | 고칠수록 나빠지는 상태. 로그를 남기고 사람에게 넘긴다 |
| QA 2회 연속 FAIL | 같은 이유 |
| develop 머지(`md`) 충돌 · push 실패 | 테섭은 다른 작업의 커밋이 섞이는 곳이라 임의로 해결하지 않는다. **PR의 base 충돌은 여기 해당하지 않는다** — [`/gs:pr`](skills/pr/SKILL.md)이 base를 merge해 바로 해결한다 |
| 노션 페이지 접근 실패 | 기록할 곳이 없으면 자동 결정을 남길 자리도 없다 |

권한·시크릿으로 막힌 것은 **여기 해당하지 않는다.** 위 §권한·시크릿대로 대체 경로까지 시도한 뒤, 안 되면 그 항목만 건너뛰고 나머지를 끝낸다 — 전체를 멈추지 않는다.

멈출 때는 어디서 왜 멈췄는지와 상태 파일 경로를 남긴다.

## 보고 의무

안 묻는 대신 **검토할 수 있어야 한다.** 검토 자리는 두 곳이고 형식이 다르다.

- **사전 — 게이트의 설계 설명.** 설계 확정 전까지 AI가 정한 것은 목록으로 내지 않고 설계 설명 안에 녹인다. 되돌리는 비용 `높음`은 굵게, 빠짐없이. 형식은 [`/gs:design`](skills/design/SKILL.md) ⑥.
- **사후 — 구현 이후 마지막 출력.** 확정 뒤 구현·QA 중에 AI가 정한 것은 설계 설명이 이미 지나간 뒤라 목록으로 남긴다. `/gs:implement`·`/gs:implement-loop`의 마지막 출력과 PR 본문에 반드시 아래가 들어간다.

```
AI가 정한 것 (n건):
1. <무엇> — 채택: <값> · 되돌리는 비용: <등급>
2. …                                     ← 없으면 "AI가 정한 것: 없음"

자동 작성 문서 — 검토 권장:              ← 이번 실행에서 새로 쓴 것만
- docs/architecture.md
```

- **되돌리는 비용 `높음` 항목은 접지 않고 전부 편다.** 나머지가 6건을 넘으면 앞 5건만 펴고 "그 외 n건 — 작업카드 `## 논의 필요` 참조".
- 자동 작성한 프로젝트 문서(정체·아키텍처·디자인 시스템)는 이후 모든 작업이 그 위에 쌓이므로 **항상 노출한다.**

## 하지 않는 것

- 자동 결정을 기록 없이 넘기지 않는다. 기록이 빠지면 그건 자율이 아니라 은폐다.
- 정지 조건을 자동 결정으로 우회하지 않는다.
- `--force` push · `--no-verify` · hook 우회를 하지 않는다. 자율 모드는 되돌릴 수 있는 범위 안에서만 돈다.
- 권한·시크릿이 필요해 보인다고 사람에게 되묻지 않는다. MCP로 먼저 시도하고, 막히면 보고한다.
- 시크릿 값을 노션·PR 본문·에이전트 프롬프트·보고에 적지 않는다. 키 이름까지다.
- 사람이 직접 부른 `/gs:interview`를 조용히 만들지 않는다. `/gs:problem-log`는 누가 부르든 조용히 만들지 않는다.
