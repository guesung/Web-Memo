# /gs:idea — 아이디어 → 기획 확정 → 작업 페이지

회사판(`/nudge:work-card`)은 슬랙 스레드에서 기획을 **받아온다.** 개인 프로젝트에는 기획을 주는 사람이 없으므로, 이 스킬이 그 앞단을 **만든다.** 기획 초안도 확정도 AI가 하고, 사람은 `/gs:design` ⑥에서 기획서와 설계서를 한 번에 본다 — 도장을 두 번 받으면 자율 모드가 성립하지 않는다.

```
/gs:discuss    (다른 입구) 사람과 같이 기획·설계 → 확정 → implement-loop — 항상 묻는다
               도중에 멈추면 합의(`## 논의`)를 들고 여기로 넘어온다
      │
      ▼
/gs:idea       기획서 자동 확정 · 개인 페이지 · 설계서 씨앗     — 묻지 않는다
      │  └─ ② /gs:interview --auto  결정 필요를 추천안으로 확정
      ▼
/gs:design     (UI 있으면 designer) → AS-IS/TO-BE · 변경 지점 → 설계 설명 → ★ 승인
      │  └─ ⑤ /gs:interview --auto  논의 필요를 추천안으로 확정
      ▼
/gs:implement-loop  구현 → 셀프 QA → 테섭 배포 → PR             — 묻지 않는다
```

**입구는 둘이다.** 이 스킬은 **AI가 정하는** 입구이고, [`/gs:discuss`](../discuss/SKILL.md)는 **사람과 같이 정하는** 입구다. discuss에서 끝까지 확정한 카드는 이 스킬을 거치지 않고 `/gs:implement-loop`로 간다. discuss를 도중에 멈추고 넘어온 카드는 합의가 `## 논의`에 쌓인 채로 들어오고, 이 스킬은 나머지만 정한다. **`/gs:idea`부터 시작하면 AI가 알아서 기획부터 진행한다** — 사람의 의견이 들어갈 자리는 `/gs:design` ⑥ 승인뿐이다.

**이 스킬은 사람에게 묻지 않는다.** 파이프라인 전체에서 사람이 개입하는 자리는 `/gs:design` ⑥ 하나뿐이고, 여기서 만든 기획서는 거기서 설계서와 **함께** 검토된다. 안 묻는 대신 정한 것을 전부 기록하는 규약은 [autonomy.md](../../autonomy.md)가 SSOT다.

## 노션 접근

**시작 전에 [notion-databases.md](../../notion-databases.md#개인-업무-로그)를 읽는다.** 식별자·속성·본문 골격이 거기 있다. 개인 DB는 **`notion-home` MCP**로만 읽고 쓴다.

**본문은 `# AI 작성` 아래만 고친다.** `# 인간 작성` 아래는 읽기만 한다 — [AI 작성 경계](../../notion-databases.md#ai-작성-경계).

## §0. 시작 전 확인

1. **인자 파싱.**
   - `notion.com/…` → 기존 페이지 재개. `## 기획서`에 확정 도장이 있으면 **`/gs:design <페이지 URL>`을 그대로 이어서 실행한다**(안내하고 멈추지 않는다). 없으면 ②(결정 필요 해소)부터 이어간다.

     **`## 논의`가 있으면 읽는다.** [`/gs:discuss`](../discuss/SKILL.md)에서 사람이 합의한 결정이므로 **확정된 입력**이다. ①에서 planner 프롬프트에 항목 **원문**을 함께 넣고(요약하지 않는다), ②의 `--items`에서는 이미 합의된 지점을 뺀다 — 사람이 정한 것을 AI 추천안으로 다시 정하지 않는다. 기획서 초안이 합의와 어긋나면 합의가 이긴다. 이 경우 `## 논의` 항목이 어디에 반영됐는지를 ④의 `## 논의 필요`에 한 줄씩 남긴다.

     페이지 URL을 확보했으므로 **[orca-worktree.md](../../orca-worktree.md)의 절차대로 현재 워크스페이스 메모에 기록한다.** 실패해도 멈추지 않는다.
   - 그 외 텍스트 → 아이디어. ①로 간다.
   - 없으면 멈추고 아이디어를 요구한다.
2. **범위 확인 — cashwalk 안이면 시작하지 않는다.** `--repo`가 `레포지토리/cashwalk/` 아래면 한 줄 남기고 멈춘다: `회사 작업은 /nudge:work-card 로 시작하세요. 이 플러그인은 개인 프로젝트 전용입니다.` 회사 기획을 개인 파이프라인에 태우면 팀 카드·원장과 어긋난다.
3. **레포 판정 — 묻지 않고 정한다.** `--repo`가 있으면 그것이다. 없으면 아이디어 내용으로 `~/Desktop/레포지토리/guesung/` 아래 기존 레포 후보를 찾아 아래 순서로 판정한다.

   | 상황 | 판정 |
   |---|---|
   | 후보 1개 | 그 레포에 얹는다 |
   | 후보 2개 이상 | 아이디어와 겹치는 도메인이 큰 쪽 → 같으면 최근 커밋이 새로운 쪽 |
   | 후보 0개 | 신규 프로젝트 |

   판정 결과를 `[AI 자동 결정]`으로 ④의 `## 논의 필요`에 남긴다 — 후보와 왜 그쪽을 골랐는지까지. 레포를 잘못 고르면 설계 전체가 헛돌므로, `/gs:design` ⑥ 설계 설명에서도 이 판단을 밝힌다.
4. **프로젝트 정체 문서 확인.** `<레포>/docs/project-identity.md`를 읽는다. 있고 내용이 차 있으면 ①로 간다. **없거나 `TBD`뿐이면 여기서 채운다** — 기획의 바닥이 없는 채로 planner를 띄우면 방향이 다른 기능이 그럴듯하게 들어온다.

   1. **묻지 않고 채운다.** [project-docs.md의 인터뷰 질문](../../project-docs.md#인터뷰-질문--정체) 여섯 개에 대한 답을 **아이디어 문장 → 기존 레포(README·기존 화면·의존성) → 다른 개인 레포의 정체 문서** 순서로 찾는다.
   2. 답을 [정체 문서 골격](../../project-docs.md#골격--정체) 여섯 항목으로 옮긴 초안을 만든다. **살을 붙이지 않는다** — 아이디어 문장에 있는 말을 그대로 옮기고, 근거가 없는 항목은 지어내지 말고 `추정: <내용>`으로 표시한다.
   3. 승인 없이 쓴다. **기존 레포면** `<레포>/docs/project-identity.md`에, **신규 프로젝트면** 아직 레포가 없으므로 파일 대신 ④의 `## 기획서` 맨 아래에 `### 프로젝트 정체`로 붙여 둔다 — 스캐폴딩 직후 `/gs:implement`가 이걸 파일로 옮긴다.
   4. **자동 작성 사실을 반드시 노출한다.** 마지막 출력의 `자동 작성 문서 — 검토 권장`에 경로를 올리고, `추정:` 항목은 `[AI 자동 결정]`으로 `## 논의 필요`에도 남긴다.

   이 문서 위에 이후 모든 기획이 쌓이지만, 그렇다고 아이디어가 떠오른 순간에 여섯 번 묻는 것은 자율 모드가 아니다. 대신 `/gs:design` ⑥ 설계 설명의 `자동 작성 문서`에 올리고 `추정:` 항목을 설명 안에서 밝혀, 사람이 그 자리에서 잡게 한다.

## ① 기획 초안 — planner 에이전트

`Agent` 도구로 `gs:planner`를 띄운다. 프롬프트에는 **아이디어와 레포 경로(있으면)만** 넣는다. 정체 문서는 planner가 레포에서 직접 읽는다 — 메인 컨텍스트가 요약해 넘기면 어느 줄이 사람의 말이고 어느 줄이 요약인지 planner가 구분하지 못한다. 신규 프로젝트라 파일이 없으면 §0-4에서 자동 작성한 초안 **원문**을 프롬프트에 함께 넣는다.

planner 출력에 `## 정체 문서와의 충돌`이 있으면 **②의 `--items` 맨 앞에 둔다.** 방향이 어긋난 채로 세부를 정해봐야 다 버리므로, `/gs:interview`가 상위 결정으로 먼저 채택하게 한다. 채택 결과는 `[AI 자동 결정]`에서 되돌리는 비용 `높음`으로 표시해 ⑥ 설계 설명에서 굵게 드러나게 한다.

결과의 `기획서 초안` 6항목과 `결정 필요` 목록을 받는다. **에이전트가 낸 초안을 메인 컨텍스트가 다듬지 않는다.** 바뀌는 건 ②의 결정 반영뿐이다 — 메인 컨텍스트가 손대기 시작하면 어디까지가 에이전트 판단인지 나중에 사람이 알 수 없다.

## ② 결정 필요 해소 — `/gs:interview --auto` 호출

planner가 낸 `결정 필요` 목록을 **`--items`로 넘기고 `--auto`를 붙여 [`/gs:interview`](../interview/SKILL.md)를 호출한다.** 프롬프트에는 확정 전 기획서 초안과 레포 경로(있으면)를 맥락으로 함께 넣는다. 조사 우선·추천 채택·보수적 선택 규칙은 그 스킬이 갖고 있다 — 여기서 다시 정하지 않는다.

`--page`는 넘기지 않는다. 아직 페이지가 없고, 기록은 ④에서 이 스킬이 한다.

반환받은 네 표를 이렇게 쓴다.

| 반환 섹션 | 여기서 하는 일 |
|---|---|
| `AI가 정한 것 (높음/중간)` | 기획서 초안에 반영하고, 표 전체를 ④의 `## 논의 필요`에 `[AI 자동 결정]`으로 남긴다. `/gs:design` ⑥ 설계 설명에 녹아 들어간다 |
| `조사로 답한 것` | 근거가 기획서와 어긋나지 않는지만 확인하고 반영한다 |
| `내가 정한 것 (낮음)` | 반영한다. 마지막 출력에 건수만 알린다 |
| `미해소` | `--auto`에서는 비어 있어야 정상이다. 차 있으면 그 항목만 `## 논의 필요`에 남기고 진행한다 |

- **미해소가 있어도 멈추지 않는다.** 기획 층위의 미결은 설계서를 만들어 봐야 판단할 수 있는 것이 대부분이고, 사람의 검토 자리는 `/gs:design` ⑥에 있다.
- 되돌리는 비용 `높음` 항목은 `## 논의 필요`에서 **맨 위에** 둔다.

## ③ 기획 자동 확정

묻지 않는다. ④로 가서 `## 기획서` 첫 줄에 도장을 찍는다.

```
> 기획 자동 확정 · 2026-09-13 14:20 · AI (검토는 /gs:design ⑥에서)
```

**"사람 승인"이라고 적지 않는다.** 도장 문구가 실제로 누가 확정했는지를 말해야, 나중에 페이지만 보고도 검토를 받은 기획인지 알 수 있다. `/gs:design` ⑥에서 사람이 승인하면 그 스킬이 이 줄 아래에 `> 기획 확인 · <시각> · 사람 승인 (/gs:design ⑥)`을 더한다. `/gs:discuss`에서 확정하면 `> 기획 확인 · <시각> · 사람 합의 (/gs:discuss)`다.

## ④ 개인 작업 페이지

1. **중복 확인.** `API-query-data-source`로 최근 페이지 `이름`을 훑는다. 같은 기획명이 있고 `상태`가 `진행 중`이면 **묻지 않고 그 페이지를 재사용**한다(같은 작업을 두 카드로 쪼개는 쪽이 더 비싸다). `완료`면 새로 만들고 `## 논의 필요`에 이전 페이지 URL을 한 줄 남긴다.
2. **생성** (`API-post-page`, parent = 개인 업무 로그 data source). 속성: `이름`=기획명(짧은 명사구), `프로젝트`=[레포 경로 ↔ 프로젝트](../../notion-databases.md#레포-경로--프로젝트) 판정(신규 프로젝트면 비움), `작업 시작 날짜`=오늘. **`상태`는 쓰지 않는다** — 사람과 러너가 관리하는 값이라 속성을 생략해 노션 기본값에 맡긴다.
3. **본문 골격** (`API-patch-block-children`). [본문 골격](../../notion-databases.md#본문-골격)대로 목차 · `# 인간 작성`(+ `### 기획`·`### 설계`) · `# AI 작성` 을 만들고, 여덟 제목을 그 이름 그대로 **`# AI 작성` 아래에** 만든다 — design·implement·implement-loop가 제목으로 섹션을 찾는다.

   `API-post-page`로 만든 페이지에는 DB 기본 템플릿이 적용되지 않는다. 두 H1을 여기서 만들지 않으면 사람이 쓸 자리가 영영 생기지 않는다. `# 인간 작성` 아래 두 제목은 **비운 채로** 둔다 — 사람 자리다.
4. `## 기획서`에 확정된 6항목(+도장)을, `## 설계서`에 씨앗을 쓴다.
5. **워크스페이스 메모 기록.** 만들어진 페이지 URL을 **[orca-worktree.md](../../orca-worktree.md)의 절차대로** 현재 orca 워크스페이스 메모에 남긴다. 실패해도 멈추지 않는다 — 마지막 출력에 한 줄만 남긴다.

**설계서 씨앗은 두 가지만:**

1. **한 줄 목표** — 기획서의 MVP 범위를 한 문장으로
2. **범위 밖** — 기획서의 범위 밖 그대로

`## 디자인`·`## TDL`·`## QA 체크리스트`·`## 해결한 문제`·`## 루프 로그`는 뒤 단계가 채운다. 지금은 비워 둔다.

## 마지막 출력

여섯 줄. 그 이상 쓰지 않는다.

```
기획: 자동 확정 <시각>
인터뷰: AI가 정한 n건(높음 n·중간 n) · 조사로 답한 n건 · 낮음 n건
개인 페이지: <URL>
워크스페이스 메모: 기록함 (또는 "건너뜀 — orca 밖" / "기록 실패 — <사유>")
레포: <경로> — <왜 이 레포인지 한 줄> (또는 "신규 — design에서 스캐폴딩 계획")
정체 문서: <경로> 자동 작성 (추정 n항목) / 기존 (또는 "기획서에만 기록 — 신규 프로젝트")
```

그리고 **묻지 않고 `/gs:design <페이지 URL>`을 이어서 실행한다.** 여기서 멈추면 사람이 다시 명령을 쳐야 하고, 그건 승인이 아니라 대기다.

## 하지 않는 것

- **`AskUserQuestion`을 부르지 않는다.** 이 스킬에는 사람에게 묻는 자리가 없다. 갈리는 것은 추천안을 채택하고 `[AI 자동 결정]`으로 남긴다.
- 도장에 "사람 승인"이라고 적지 않는다. AI가 확정한 것은 AI가 확정했다고 적는다.
- 정한 것을 기록 없이 넘기지 않는다. `/gs:design` ⑥ 설계 설명이 이 기록을 재료로 쓴다.
- 기술 스택·구현 방식을 정하지 않는다. design 몫이다. 정체 문서에도 스택을 적지 않는다 — 그건 `docs/architecture.md` 자리다.
- 코드를 쓰지 않는다.

## 왜 이렇게 나눴나

- **planner를 별도 에이전트로 두는 이유** — 기획과 구현을 같은 컨텍스트가 하면, 구현하기 쉬운 쪽으로 기획이 휜다. 컨텍스트를 끊어야 "만들기 어렵지만 문제를 푸는 기능"이 살아남는다.
- **기획 도장을 사람에게서 뺀 이유** — 층마다 도장을 받으면 되돌아가는 거리는 짧아지지만, 사람이 같은 작업에 두 번 불려 나온다. 개인 프로젝트에서는 그 왕복이 완성까지의 속도를 깎는 가장 큰 비용이었다. 대신 기획서를 **설계서와 함께** `/gs:design` ⑥ 설계 설명에 함께 담아, 한 번의 검토가 두 층을 다 덮게 했다. 기획이 틀렸으면 거기서 잡히고, 그때 되돌리는 거리는 설계서 한 장이다.
- **회사판 work-card와 갈라진 이유** — work-card는 이미 있는 기획(슬랙)을 노션으로 옮기는 스킬이고, 이 스킬은 없는 기획을 만드는 스킬이다. 입력이 다르면 스킬도 다르다. 팀 카드·스레드 모음 로직은 개인에 존재하지 않으므로 가져오지 않았다.
