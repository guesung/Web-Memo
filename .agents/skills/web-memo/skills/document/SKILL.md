# /web-memo:document — 웹 메모 문서 기록

사용자가 지정한 대화 내용이나 자료를 개인 Notion의 웹 메모 프로젝트 문서로 남기고 링크를 반환한다. 단순 질문에는 문서를 자동 생성하지 않는다.

## 대상과 입력

- 기본 대상과 식별자는 `~/.agents/docs/notion-databases.md`의 `웹 메모 프로젝트 문서` 절에서 읽는다. 업무 로그·개발 위키와 혼동하지 않는다.
- 사용자가 다른 저장 위치를 명시하면 그 위치를 조회해 따른다.
- "위에서 작성한 내용"은 해당 대화의 답변을 뜻한다. 결론·근거·우선순위·제약·출처를 보존해 문서화한다. 요약 요청이 없으면 핵심 논점을 누락하는 짧은 요약으로 대체하지 않는다.
- 대상 내용이 하나로 정해지지 않을 때만 무엇을 기록할지 한 번에 하나씩 묻는다. 제목은 내용에서 정한다.

## 연결과 위치 확인

1. 사용 가능한 개인 Notion 연결을 확인한다. 도구 선택은 [Notion 접근 규칙](../../notion-access.md)을 따른다. 연결 이름보다 실제 대상 조회 성공을 확인하며, 회사 계정으로 임의 대체하지 않는다. 접근 불가 시 비밀값을 요청하거나 저장 성공을 주장하지 않는다.
2. 목적지 DB와 사용자가 준 뷰를 조회해 데이터 소스·속성·필터를 확인한다. 연결 도구가 제공하는 Markdown 명세를 읽고 지원하는 형식으로 작성한다.
3. 기본 뷰의 `Projects DB` 관계가 웹 메모 프로젝트를 포함하는지 확인한다. `프로젝트=웹 메모`만 설정하면 관계 필터를 통과하지 못한다. `선택=Legacy`도 해당 뷰에서 제외된다. 카탈로그의 관계 대상이 여전히 웹 메모인지 검증한다.
4. 같은 내용의 문서가 있는지 검색한다. 새 페이지 요청이면 기존 문서를 덮어쓰지 않는다. 직전 생성 응답이 불확실한 재시도라면 생성 여부부터 확인해 중복을 방지한다.

## 작성과 저장

- 문서 구조는 내용에 맞춰 정한다. 조언·계획이라면 목표, 현재 근거와 한계, 우선순위별 제안, 검증 방법, 다음 작업, 출처가 유용하다. 업무 로그용 인간/AI H1 골격을 강제하지 않는다.
- 제안·가설·미확인을 사실·실행 결과·승인으로 바꾸지 않는다. 현재 운영 수치를 조회하지 않았다면 그 한계를 남긴다. 외부 링크와 저장소 근거를 보존하고, 확인하지 않은 최신 정보나 출처를 덧붙이지 않는다.
- 정확한 데이터 소스에 새 페이지를 만든다. 기본 속성은 제목, `프로젝트=웹 메모`, 검증된 `Projects DB` 관계, KST 오늘의 `추가된 날짜`, `AI 작성=true`, `공개=false`다. 현재 스키마에 있는 값만 사용한다. 본문 저장이 완료되면 `상태=작성 완료`로 둘 수 있으며, 이는 제안의 승인이나 개발 완료를 뜻하지 않는다. 유형·태그는 맞는 기존 옵션이 있을 때만 고른다.
- 공개 설정·새 옵션·DB 스키마·다른 페이지를 변경하지 않는다. 작업 카드 생성, 실행 요청, 구현·배포는 이 스킬의 범위 밖이다.
- 생성 결과에서 경고·누락을 확인한다. 응답에 필터 속성이 없거나 저장이 불확실하면 페이지를 다시 조회해 목적지·본문·관계를 확인한다. 부분 성공은 링크와 미완료 지점을 보고하며, 같은 페이지를 무작정 다시 생성하지 않는다.

## 결과

문서 링크와 제목, 저장 위치를 짧게 보고한다. 기록 내용이 제안 단계라면 승인·실행 완료처럼 표현하지 않는다.
