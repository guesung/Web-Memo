# /bug-log — 버그 해결 기록을 Notion에 남기기

방금 해결한 버그를 Notion에 기록합니다. 대상 DB는 다음 한 곳입니다.

```
https://app.notion.com/p/guesung/02b230957fc742a982f2f09d2d556e41
```

> 작업 전반의 기록은 `/add-docs`, 노션 작업카드 갱신은 `/card-log`입니다.
> 이 커맨드는 **버그 하나의 원인 규명 기록**만 다룹니다.

## 이 커맨드를 쓰는 시점

- 원인을 특정하고 고쳐서 검증까지 끝냈을 때
- 원인이 **당장 짐작되지 않던** 버그였을 때 (한눈에 보이는 오타 수정은 대상이 아님)
- 특히 아래에 해당하면 반드시 남깁니다
  - 며칠 이상 CI가 깨져 있었거나 아무도 원인을 몰랐던 것
  - 한 환경에서만 터져서 발견이 늦은 것 (앱만, 프로덕션만, CI만)
  - 원인이 증상과 멀리 떨어져 있던 것

## 수행 절차

### 1. 근거 수집

아래를 **병렬로** 실행해 사실을 모읍니다.

- `git log --oneline -15` — 이번 작업 커밋
- `git diff origin/master...HEAD` — 실제 변경 내용
- `git branch --show-current`
- `gh pr view --json number,title,url` — PR 정보 (있으면)
- 회귀라면 마지막 성공 시점을 찾습니다 (`gh run list`, `gh api .../actions/runs`)

**대화에서 이미 확인한 로그·에러 메시지·실행 결과를 그대로 씁니다.** 기억으로
재구성하지 않습니다. 근거가 없는 항목은 채우지 말고 비웁니다.

### 2. DB 스키마 확인 (건너뛰지 말 것)

페이지를 만들기 **전에** 위 URL을 Notion MCP의 fetch 도구로 조회해서
데이터 소스 ID와 속성(properties) 목록을 확인합니다.

- 속성 이름은 추측하지 않습니다. 조회 결과에 있는 이름을 그대로 씁니다.
- 조회한 속성 중 채울 수 있는 것만 채웁니다. 없는 속성을 만들지 않습니다.
- 제목 속성에는 **증상이 드러나는 한 줄**을 넣습니다.
  - 좋음: `iOS 빌드가 @web-memo/env 해석 실패로 6일간 깨짐`
  - 나쁨: `버그 수정`, `iOS 이슈`

### 3. 본문 작성

아래 구조를 따릅니다. **해당 없는 절은 통째로 생략합니다.**

```
## 증상
관측된 것만. 에러 메시지는 원문 그대로 코드 블록에.
언제부터, 어디서(어느 워크플로/환경), 몇 번이나 터졌는지.

## 영향 범위
무엇이 막혔고 무엇은 멀쩡했는지.
한 환경에서만 터졌다면 왜 다른 환경에서는 안 드러났는지.

## 원인
증상에서 원인까지의 연결 고리를 순서대로.
파일:줄 번호로 지목하고, 추측과 확인된 사실을 섞지 않는다.

## 왜 지금 터졌나
회귀라면 마지막 성공 시점과 그 사이 무엇이 바뀌었는지.
원래부터 잠재해 있었다면 무엇이 그것을 드러냈는지.

## 해결
바꾼 것과 그렇게 고른 이유. 검토했지만 택하지 않은 대안이 있으면 왜 아닌지.

## 검증
어떻게 증명했는지. 재현 → 수정 → 재확인이 이상적이다.
"테스트 통과"만 쓰지 말고 무엇을 어떤 조건에서 돌렸는지 적는다.

## 재발 방지
문서·가드·컨벤션으로 남긴 것. 없으면 "없음"이라고 쓰고 이유를 적는다.

## 참고
PR 링크, 커밋 해시, CI 실행 링크.
```

### 4. 페이지 생성

Notion MCP의 페이지 생성 도구로 만듭니다.

- `parent`는 2단계에서 확인한 데이터 소스 ID를 씁니다.
- 날짜 속성이 있으면 오늘 날짜를 ISO-8601(`YYYY-MM-DD`)로 넣습니다.

### 5. 결과 보고

생성된 페이지 URL을 사용자에게 전달합니다.

## 주의

- **추측을 사실처럼 쓰지 않습니다.** 확인 못 한 것은 "확인하지 않음"이라고 적거나
  뺍니다. 원인 문서에서 틀린 단정은 다음 사람을 잘못된 방향으로 보냅니다.
- **에러 메시지·로그는 원문 그대로** 옮깁니다. 요약하면 나중에 검색이 안 됩니다.
- 여러 버그를 한 페이지에 묶지 않습니다. 하나당 한 페이지입니다.
- 코드에 이미 드러나 있는 내용(무엇을 바꿨는지)보다 **왜 그게 원인이었는지**에
  분량을 씁니다. 전자는 diff를 보면 되지만 후자는 기록해야만 남습니다.
- 커밋 메시지를 그대로 복사해 붙이지 않습니다. 커밋은 변경을 설명하고,
  이 문서는 조사 과정을 설명합니다.
- Notion MCP가 연결돼 있지 않으면 인증을 안내하고 중단합니다.
  본문을 파일로 대신 저장하지 않습니다.

## 인자

`$ARGUMENTS` — 기록할 버그를 특정하는 힌트 (선택). 한 세션에서 여러 버그를
고쳤을 때 어느 것을 남길지 지정합니다.
