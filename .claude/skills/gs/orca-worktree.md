# orca 워크스페이스 메모 기록 규칙

작업카드(개인 업무 로그 페이지) URL과 PR 제목·URL을 **현재 orca 워크스페이스의 메모**에 남기는 규칙의 단일 진실 공급원(SSOT)이다.
노션 페이지 URL을 만들거나 인자로 받는 스킬은 **§0(시작 전 확인)에서 이 파일을 읽고 아래 절차를 그대로 수행한다.**

메모는 orca 워크스페이스 카드에 그대로 보이는 필드다. 여기에 URL이 있으면, 워크트리 목록만 보고도 **이 브랜치가 어느 작업카드의 것인지** 알 수 있다.

## 언제

| 시점 | 스킬 |
|---|---|
| 작업 페이지를 **새로 만든 직후** | `/gs:idea` ④ |
| 페이지 URL을 **인자로 받아 시작할 때** | `/gs:design`, `/gs:discuss`, `/gs:implement`, `/gs:implement-loop`, `/gs:self-qa`, `/gs:problem-log`·`/gs:blog-material`(`--work-card`) |

`/gs:interview`는 하지 않는다 — 항상 `/gs:idea`·`/gs:design` 안에서 호출되고, 그 둘이 이미 기록한 뒤다.

위 작업카드 기록은 두 경우 모두 **URL을 확보한 직후 한 번** 수행한다. 뒤 단계에서 다시 쓰지 않는다 — 같은 값을 반복해서 덮는다. **PR 기록은 예외**이며, `/gs:pr` 생성 성공 직후 아래 **PR 기록 절차**를 수행한다.

## 절차

1. **현재 워크트리 확인.**

   ```bash
   orca worktree current --json
   ```

   실패하거나 `ok: false`면 **여기서 조용히 멈춘다.** orca 밖에서 실행 중이라는 뜻이고, 그건 오류가 아니다.

2. **기존 메모 확인.** 결과의 `result.worktree.comment`를 읽는다.

   - 이미 `작업카드: <같은 URL>` 줄이 있으면 **아무것도 하지 않는다.**
   - 다른 URL의 `작업카드:` 줄이 있으면 **그 줄만 새 URL로 바꾼다.**
   - `작업카드:` 줄이 없으면 **맨 앞 줄로 끼워 넣고 기존 내용은 그 아래에 그대로 둔다.**

   기존 메모를 통째로 날리지 않는다. 메모는 사람이 손으로 쓰는 칸이기도 하다.

3. **쓴다.**

   ```bash
   orca worktree set --worktree current --comment "작업카드: <URL>" --json
   ```

4. **실패해도 파이프라인을 멈추지 않는다.** 마지막 출력에 한 줄만 남긴다: `워크스페이스 메모: 기록 실패 (<사유>)`.

## 형식

작업카드 첫 줄은 항상 이 한 줄이다. 작업카드에는 제목·상태 같은 걸 덧붙이지 않는다 — 그건 노션이 갖고 있고, 메모에 복제하면 둘이 어긋난다.

```
작업카드: https://www.notion.so/...
```

PR 기록에는 아래 별도 형식에 따라 제목과 URL을 함께 남긴다. 위 제목 금지 규칙은 작업카드에만 적용한다.

## PR 기록 절차

작업카드 기록의 횟수·형식 제한과 별개로, PR 생성·재사용·갱신에 성공한 뒤 수행한다. 메모 기록 실패 때문에 성공한 PR을 다시 만들거나 PR 작업을 취소하지 않는다.

1. **확정된 PR 정보 확보.** 생성·갱신한 PR의 URL 또는 번호를 지정해 `gh pr view <PR URL 또는 번호> --json title,url`로 실제 제목과 URL을 읽는다. 메모에는 제목의 개행(`\r`, `\n`)을 공백으로 바꾼 한 줄 제목을 사용한다. PR 생성·재사용·갱신 자체가 실패했으면 메모도 쓰지 않는다.
2. **현재 워크스페이스와 메모 조회.** PR을 작업한 디렉터리(cwd)를 유지한 채 `orca worktree current --json`을 실행하고 `result.worktree.comment`를 읽는다. 다른 워크스페이스를 이름으로 추측하거나 디렉터리를 바꾸지 않는다. `null` 메모만 빈 문자열로 취급하고, 응답 구조가 예상과 다르면 쓰지 않는다.
3. **URL 중복 확인 및 추가.** 기존 메모에서 URL 전체가 같은 항목이 있으면 쓰지 않는다. 부분 문자열 비교로 `/pull/12`와 `/pull/123`을 같은 URL로 취급하지 않는다. 없으면 기존 메모 **전체를 한 글자도 변경하지 않고**, 맨 뒤에 아래 한 줄을 추가한다. 기존 메모가 비어 있지 않고 개행으로 끝나지 않을 때만 구분 개행을 추가한다. 작업카드·팀카드·슬랙·사람이 쓴 메모 및 다른 PR 기록은 모두 보존한다.

   ```text
   PR: <한 줄 제목> — <PR URL>
   ```

4. **병합한 전문을 안전하게 전달.** `orca worktree set --worktree current --comment "$MERGED_COMMENT" --json`을 실행한다. `MERGED_COMMENT`에는 새 PR 줄만이 아니라 기존 메모와 합친 전문이 들어 있어야 한다. JSON 파서로 읽은 문자열을 인자 배열의 단일 인자로 전달하는 방식을 우선한다. 셸을 사용하면 변수를 반드시 큰따옴표로 감싸고, 제목·메모를 명령 문자열에 직접 끼워 넣거나 `eval`로 실행하지 않는다. 따옴표·백틱·`$`·기존 개행을 그대로 보존한다.
5. **재조회 검증.** 쓰기 명령의 성공 종료와 `ok: true`를 확인한 뒤, 같은 cwd에서 `orca worktree current --json`을 다시 실행한다. 조회한 `result.worktree.comment`가 병합한 전문과 정확히 일치하는지 확인한다. 다르면 성공으로 보고하지 않고, 기존 메모로 다시 덮어쓰지도 않는다.
6. **별도 실패 안내.** PR 정보 조회, Orca 미설치·현재 워크스페이스 없음, JSON 조회·쓰기·재조회 검증 중 어느 단계든 실패하면 메모 기록만 중단한다. 작업카드 절차의 조용한 종료와 달리, PR 결과와 별도로 `워크스페이스 메모: 기록 실패 (<사유>)`를 한 줄 알린다. 중복으로 쓰기를 생략했거나 재조회 검증에 성공했으면 추가 보고는 필요 없다.

## 카드 없음 확인

노션 URL 없이 시작하는 작업(`/gs:implement`의 파일·지시 모드, `/gs:implement-loop`의 설계서 파일 모드)은 메모에 작업카드가 없다. 이때 **카드를 새로 만들지 사람에게 묻는다.** 자율 모드의 예외다 — [autonomy.md](autonomy.md).

1. `orca worktree current --json`으로 메모를 읽는다. 실패하거나 `ok: false`면 **조용히 넘어간다.** 메모에 `작업카드:` 줄이 이미 있어도 넘어간다.
2. `작업카드:` 줄이 없으면 `AskUserQuestion`으로 묻는다: `이 워크스페이스 메모에 작업카드가 없습니다. 새 작업 카드를 만들까요?` (선택지: `만든다` / `카드 없이 진행`).
3. **`카드 없이 진행`** 을 고르면 그대로 진행한다. 이번 실행에서는 다시 묻지 않는다.
4. **`만든다`** 를 고르면 빈 카드만 만든다 — 기획·설계 단계는 돌리지 않는다.
   - [/gs:idea ④](skills/idea/SKILL.md)의 2·3·5와 같다: `API-post-page`로 생성 → 본문 골격 → 위 **절차**로 메모 기록. 중복 확인(①)은 건너뛴다.
   - 속성 `이름`은 지시문·설계서 제목을 줄인 짧은 명사구, `프로젝트`는 [레포 경로 ↔ 프로젝트](notion-databases.md#레포-경로--프로젝트) 판정, `작업 시작 날짜`는 오늘이다. `상태`는 쓰지 않는다.
   - `## 설계서`에는 한 줄 목표(지시문 요약)만 쓴다. 나머지 섹션은 비워 둔다.
   - 만든 URL은 이후 이 실행의 **노션 URL**로 취급해 `ID`를 읽고 PR 제목 접두사에 쓴다.
5. 생성에 실패하면 멈추지 않고 카드 없이 진행하며, 마지막 출력에 `작업카드: 생성 실패 (<사유>)` 한 줄을 남긴다.

`--from-loop`로 불린 `/gs:implement`는 묻지 않는다 — loop §0이 이미 물었다.

## 주의

- `--comment ""`(빈 문자열)로는 메모가 **지워지지 않는다.** 인자가 없는 것과 같이 취급된다. 이 규칙은 지우는 일이 없으므로 문제되지 않지만, 지우려면 사람이 orca UI에서 해야 한다.
- `--worktree current`는 **명령을 실행하는 디렉터리** 기준이다. 다른 워크트리 얘기를 하고 있더라도 현재 디렉터리의 워크트리에 쓰인다. 그래서 이 규칙은 "지금 이 워크트리에서 진행 중인 작업카드"에만 쓴다.

## 왜

- **워크트리와 작업카드는 1:1인데 그 연결이 어디에도 없었다.** 브랜치명은 한글 작업명이라 노션 검색에 걸리지 않고, 노션 페이지에는 브랜치가 PR 링크로만 뒤늦게 붙는다. 메모 한 줄이 그 간극을 메운다.
- **재개할 때 URL을 다시 찾는 비용이 사라진다.** 며칠 뒤 워크트리로 돌아왔을 때 `/gs:design`에 붙여넣을 URL이 카드에 이미 적혀 있다.
