# /gs:issue-solve — 리포트 → 진단 → 자동 해결

```
notion-orca (시작 단계=이슈 해결) → 카드 생성, `# 인간 작성`에 리포트
      │
      ▼
/gs:issue-solve
  ① 상황 파악 ── `# 인간 작성` 원문 전체 읽기 + 레포 코드 탐색 (병렬)
  ② 진단 ────── 원인 가설 + 해결책, 확신도·근거와 함께 `## 설계서`에 기록 — 묻지 않는다
      │
  --diagnose-only면 여기서 멈춘다
      │
  ③ 해결 ────── 묻지 않고 /gs:implement <페이지 URL> 이어서 실행
```

**이 스킬은 사람에게 묻지 않는다.** [autonomy.md](../../autonomy.md)가 SSOT — gs 파이프라인의 승인 자리는 `/gs:design` ⑥과 `/gs:discuss` 확정인데, 이슈 해결은 그 단계를 거치지 않는 별도 입구다. 오진단 위험은 승인 게이트가 아니라 확신도 표기 + `## 논의 필요` 기록으로 감당한다(왜 이렇게 나눴나 참고).

## 노션 접근

시작 전에 [notion-databases.md](../../notion-databases.md#개인-업무-로그)를 읽는다. `notion-home` MCP로만 접근한다.

**본문은 `# AI 작성` 아래만 고친다.** `# 인간 작성` 아래는 읽기만 한다 — [AI 작성 경계](../../notion-databases.md#ai-작성-경계).

## §0. 시작 전 확인

1. **인자 파싱.** 노션 페이지 URL 하나를 받는다(notion-orca가 넘긴다). URL이 없으면 멈추고 요구한다 — 이슈 해결은 리포트가 이미 카드에 적혀 있다는 전제이므로 자유 지시를 받지 않는다.

   페이지 URL을 확보했으므로 [orca-worktree.md](../../orca-worktree.md)의 절차대로 현재 워크스페이스 메모에 기록한다. 실패해도 멈추지 않는다.

2. **범위 확인 — cashwalk 안이면 시작하지 않는다.** 카드 속성 `프로젝트`로 [레포 경로 ↔ 프로젝트](../../notion-databases.md#레포-경로--프로젝트)를 역인용한다. `레포지토리/cashwalk/` 아래로 판정되면 한 줄 남기고 멈춘다: `회사 작업은 /nudge:issue-solve 로 진단하세요. 이 플러그인은 개인 프로젝트 전용입니다.`

3. **중복 확인.** `## 설계서`에 이미 내용이 있으면(재실행) 진단을 다시 하지 않고 그대로 ③으로 건너뛴다.

## ① 상황 파악

**원문은 스니펫이 아니라 `# 인간 작성` 전체를 읽는다.** `API-retrieve-page-markdown`으로 카드 전체를 받아 `# 인간 작성` 아래(`### 기획`·`### 설계`에 적힌 에러 로그·스택트레이스·재현 메모 포함)를 그대로 확보한다. 캡처된 로그·스택트레이스가 있으면 잘라내지 않는다.

**대상 레포를 정한다.** §0-2에서 역인용한 레포다. 같은 레포 안에서 에러 메시지 문자열·언급된 파일 경로·함수명으로 grep하고, `Explore` 에이전트로 넓게 훑는다. 이 탐색과 원문 읽기는 서로 의존하지 않으므로 **한 응답에서 병렬로** 진행한다.

원문만 읽고 코드를 보지 않으면 "그럴듯한 추측"에서 멈춘다. 실제 코드의 조건문·기본값·최근 변경 이력(`git log -p`, `git blame`)까지 봐야 원인이라고 말할 수 있다.

## ② 진단 — `## 설계서`에 기록

새 섹션을 만들지 않는다. 진단 결과를 기존 골격의 `## 설계서`에 써서 `/gs:implement`가 그대로 스펙으로 읽게 한다.

```
> 진단 자동 완료 · <시각> · AI (승인 게이트 없음 — /gs:issue-solve)

### 상황 요약
<원문에서 파악한 증상 한두 문장>

### 재현 방법
1. <단계>
2. <단계>
→ <기대 동작 vs 실제 동작>
(원문에 재현 조건이 없으면: "재현 조건 불명 — 원문에 없음")

### 원인
1. (확신 높음) <원인> — 근거: `path/to/file.ts:42`, "<코드나 로그 인용>"
2. (확신 보통) <원인> — 근거: …
3. (확신 낮음) <원인> — 근거가 약하거나 추측인 이유

### 변경 지점
- `path/to/file.ts:42` (FE/BE 태그) — 무엇을 어떻게 바꾸는지 한두 줄
```

도장 문구를 `/gs:design`의 확정 도장과 다르게 둔다 — 설계 승인을 거친 것으로 착각하지 않게 하기 위해서다.

- **확신 높음 원인을 채택해 자동으로 진행한다.** 묻지 않는다 — 원인이 여러 갈래로 갈려도 확신 높은 것을 우선 채택하고, 나머지는 `## 논의 필요`에 `[AI 자동 결정]`으로 남긴다(형식은 [autonomy.md](../../autonomy.md#자동-결정--묻지-않는-대신-남긴다)).
- **코드를 봐도 원인을 못 찾았으면 지어내지 않는다.** `### 원인`에 "확신 낮음 — 코드에서 근거를 찾지 못함"이라고 쓰고, `변경 지점`은 "재현 조건 확인 후 재진단 필요"로 남긴 채 ③으로 넘어간다 — 멈추지 않되, `/gs:implement`가 스펙 부족으로 막히면 그 스킬이 자기 규칙(보수적 선택 + 기록)대로 처리한다.

`--diagnose-only`면 여기서 멈춘다. 마지막 출력은 진단 요약과 페이지 URL만.

## ③ 해결 — `/gs:implement`로 이어감

묻지 않고 **`/gs:implement <페이지 URL>`을 그대로 이어서 실행한다.** 브랜치·TDL·커밋·머지·PR 규칙은 그 스킬이 SSOT이므로 여기서 다시 만들지 않는다. `## 설계서`의 `### 변경 지점`을 implement가 §0-4(스펙 읽기)에서 그대로 읽는다.

`/gs:implement`가 끝나면 그 결과(브랜치·PR 링크)를 그대로 전달하고 마무리한다.

**problem-log 점검은 `/gs:implement` ④가 한다** — 그 점검 범위에 이 스킬의 ①·② 진단 과정(기각한 가설, 재현에 걸린 시간)도 넣는다. 이슈 해결은 틀린 가설을 거쳐 뚫는 일이 잦아 기록 후보가 가장 많이 나오는 입구다. 여기서 따로 한 번 더 점검하지 않는다. `--diagnose-only`면 아직 뚫은 게 아니므로 점검하지 않는다.

## 마지막 출력

`--diagnose-only`:
```
진단: <상황 요약 한 줄>
원인: 확신 높음 n건 · 보통 n건 · 낮음 n건
설계서 기록: <페이지 URL>
다음 단계: /gs:issue-solve <URL> 로 이어서 구현
```

그 외에는 `/gs:implement`의 마지막 출력 그대로.

## 하지 않는 것

- **`AskUserQuestion`을 부르지 않는다.** 이 스킬에는 사람에게 묻는 자리가 없다.
- 확신 없는 원인을 확정처럼 말하지 않는다. 근거가 없으면 확신도를 낮춰서 남긴다.
- `# 인간 작성` 아래를 고치지 않는다.
- 카드를 새로 만들지 않는다 — notion-orca가 이미 만든 카드를 받는 게 전제다.
- `## 설계서`에 이미 진단이 있는데 다시 진단하지 않는다(§0-3 중복 확인).

## 왜 이렇게 나눴나

- **승인 게이트를 빼고 확신도 표기로 대체한 이유** — 회사판(`nudge:issue-solve`)은 오진단이 팀 리소스를 잘못된 방향으로 태우는 비용이 커서 승인 게이트를 둔다. 개인 프로젝트는 되돌리는 비용이 `git revert` 한 번이고, 완성 속도가 더 큰 축이다([autonomy.md](../../autonomy.md) 원칙). 대신 확신도별로 나눠 적어, 틀렸을 때 사람이 결과(PR)만 보고도 "이건 추측이었다"를 바로 알 수 있게 했다.
- **새 섹션 대신 `## 설계서`를 재사용한 이유** — `/gs:implement`는 이미 `## 설계서`·`## 디자인`·`## TDL`만 읽는다. 여기서 `## 진단` 같은 새 섹션을 만들면 implement도 그 섹션을 읽도록 고쳐야 하고, 파이프라인의 스펙 출처가 두 곳으로 갈린다. 이슈 해결의 "진단"은 결국 "무엇을 어떻게 고칠지"라는 점에서 설계서와 목적이 같다.
- **회사판 issue-solve와 갈라진 이유** — 회사판은 슬랙/노션 링크를 받아 카드가 없는 상태에서 시작하고, 진단 뒤 `/nudge:implement`에 자유 지시문으로 넘긴다. 이 스킬은 notion-orca가 이미 만든 카드에서 시작하고, 카드 자체(`## 설계서`)가 스펙이 되므로 자유 지시문을 따로 조립하지 않는다.
