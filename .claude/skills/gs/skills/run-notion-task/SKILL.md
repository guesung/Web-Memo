# /gs:run-notion-task — 노션 작업 카드 생성 후 실행 요청

이 스킬은 노션 [업무 로그 DB](https://app.notion.com/p/guesung/5f408e0500154532bcd8bd36439bec5a)에 작업 카드를 만들고, 상시 실행 중인 `notion-orca` 러너에 새 Codex 또는 Claude Code 세션을 요청한다. **`요청됨`은 실행 요청이지 세션 시작이나 작업 완료의 증거가 아니다.** Orca CLI를 별도로 실행하지 않는다.

## 입력

1. 호출 인자에 제목·작업 내용이 있으면 이를 우선 사용한다. 없으면 **현재 대화에서 사용자가 요청한 작업**만 추출해 간결한 제목과 실행 가능한 작업 내용을 만든다. 대화 전체를 복사하거나, 언급되지 않은 요구·결정·비밀값을 덧붙이지 않는다.
2. 제목과 작업 내용을 둘 다 확보할 수 없으면 **한 번에 하나씩** 사용자에게 묻는다. 추론한 내용이 여러 작업 중 무엇을 가리키는지 불명확해도 먼저 확인한다.
3. 프로젝트는 명시된 `--project`를 우선한다. 없으면 대상 저장소 경로로 판정한다: `guesung/web-memo` → `웹 메모`, `guesung/mini-projects` → `Mini Projects`, `cashwalk` 아래 → `넛지헬스케어`. 현재 디렉터리만으로 작업 대상이 확실하지 않으면 **추측하지 말고 묻는다**. 그 외 프로젝트는 러너가 지원하지 않는다.
4. `넛지헬스케어`는 `--repo` 또는 대상 저장소의 로컬 폴더명으로 `저장소`를 정한다. 데이터 소스의 기존 선택 옵션 및 Orca 등록 저장소와 정확히 일치하는지 확인한다. 없거나 일치하지 않으면 요청 전에 묻거나 중단한다. 선택 옵션을 임의로 만들지 않는다.
5. `시작 단계`는 명시된 `--stage` 또는 사용자가 지정한 단계를 사용한다. 명시되지 않았으면 새 아이디어는 `기획`, 바로 만들거나 고치는 요청은 `구현`으로 판정한다. 어느 단계인지 불명확하면 묻는다. **프로젝트·단계 조합은 작업 전 `notion-orca/runner.ts`의 `PROJECT_SKILLS`로 검증한다.** 넛지헬스케어의 `논의`·`QA`는 현재 미지원이다. `기획`은 러너가 `/nudge:work-card <노션 페이지 URL>`을 호출하지만 그 스킬은 슬랙 스레드 URL을 요구한다. 이 불일치가 해결되기 전에는 넛지헬스케어 `기획` 카드를 `요청됨`으로 만들지 않으며, 단계를 임의로 바꾸지도 않는다.
6. `실행 에이전트`는 명시된 `--agent`를 우선한다. 없으면 [`weekly-usage.sh`](weekly-usage.sh)를 실행해 출력의 `pick`을 쓴다. 이 스크립트는 Claude Code(OAuth usage API `seven_day`)와 Codex(`~/.codex/sessions` 최신 `rate_limits`의 주간 윈도우)의 주간 사용률(%)을 읽어 낮은 쪽을 고른다. 요금제 한도가 달라 토큰 절대량이 아니라 사용률로 비교한다. 같으면 `Codex`다. 한쪽만 읽혔으면(`basis=claude-only|codex-only`) 읽힌 쪽이 80% 미만일 때 그쪽, 이상이면 다른 쪽을 고르며 결과에 추정이라고 밝힌다. `pick=unknown`(둘 다 읽기 실패)이면 어느 에이전트로 할지 묻는다.
7. 후속 스킬에 필요한 선행 자료를 확인한다. 특히 넛지헬스케어 작업은 슬랙 스레드 URL·팀 카드 맥락이 필요할 수 있다. 없는 내용을 지어내지 말고 요청 전에 필요한 자료를 묻는다.

## 준비

- **`notion-home` MCP만 사용한다.** 사용할 수 없으면 카드 생성이나 실행을 했다고 주장하지 말고 중단한다.
- **`notion-orca` 코드가 동작 기준이다.** 작업 전에 `~/Desktop/레포지토리/guesung/mini-projects/apps/cli/notion-orca/notion.ts`의 `TARGET_PROJECTS`와 같은 디렉터리 `runner.ts`의 `PROJECT_SKILLS`·`buildPrompt`·`readRepositoryName`을 읽는다. `README.md`는 보조 자료이며 코드와 다르면 코드를 따른다. 현재 `웹 메모`는 러너의 `ORCA_REPO`, `Mini Projects`는 고정 저장소 `mini-projects`, `넛지헬스케어`는 카드의 `저장소`를 사용한다.
- 생성 직전에 데이터 소스 `8412989c-11e3-4685-8af9-35299fc6c097`을 조회해 `이름`(title), 정한 `프로젝트`(select), `실행 에이전트`(select: 정한 에이전트), `시작 단계`(select), `실행 상태`(select: `요청됨`)가 실제로 존재하는지 확인한다. 넛지헬스케어라면 `저장소` 옵션도 확인한다. DB ID는 `5f408e05-0015-4532-bcd8-bd36439bec5a`이다. 스키마가 맞지 않으면 쓰지 않는다.
- 현재 요청과 같은 제목·범위의 **미완료 카드가 있는지** 검색한다. 넛지헬스케어는 제목보다 슬랙 스레드 URL을 우선해 대조한다. 있으면 중복 생성하지 말고 사용자에게 기존 카드를 실행할지 묻는다. `시작됨`인 카드에 `요청됨`을 다시 설정하지 않는다.
- 생성 전에 [gs 개인 업무 로그 규약](../../notion-databases.md#개인-업무-로그)을 읽는다. 넛지헬스케어라면 `/Users/home/.agents/skills/nudge/notion-databases.md`의 개인 업무 로그 규약도 읽는다.

## 생성과 요청

1. `API_post_page`로 **실행 상태 요청 없이** 먼저 페이지를 만든다. parent는 `{"database_id":"5f408e05-0015-4532-bcd8-bd36439bec5a"}`이다. 속성은 `이름`, 정한 `프로젝트`, `실행 에이전트`(정한 에이전트), `시작 단계`, 넛지헬스케어라면 확인한 `저장소`를 설정한다. 넛지헬스케어에서 슬랙 URL이 있으면 nudge 규약대로 제목 전체에 링크를 건다. `상태`와 `실행 결과`는 러너가 관리하므로 쓰지 않는다.
2. 카드 본문을 작성한다. 사용자가 준 작업 내용은 의미를 바꾸지 않고 보존한다. 대화에서 도출한 내용은 `요청 내용`과 `참고 맥락`을 구분하며, 추론은 추론이라고 표시한다. `웹 메모`·`Mini Projects`는 gs 규약의 H1 두 개와 여덟 `##` 섹션을, `넛지헬스케어`는 nudge 규약의 H1 두 개와 여섯 `##` 섹션을 만든다. **`# 인간 작성` 영역은 비워 두고**, 요청 내용과 슬랙 URL 등 관련 링크는 `# AI 작성` 아래 적절한 섹션에 기록한다. 확정되지 않은 기획·설계에 승인 도장을 찍지 않는다.
3. 생성한 페이지를 다시 읽어 제목·프로젝트·실행 에이전트·시작 단계·본문이 모두 저장됐는지 확인한다. 실패하면 **`요청됨`으로 바꾸지 않는다**. 생성된 페이지 URL과 실패 지점을 보고한다.
4. 준비된 페이지에 `API_patch_page`로 `실행 상태`만 `요청됨`으로 설정한다. 이 단계를 **마지막에** 수행한다. 생성과 동시에 요청하면 러너가 빈 본문을 읽을 수 있다.
5. 페이지를 다시 읽어 `실행 상태`를 확인한다. `요청됨`이면 **실행 요청 완료**로 보고한다. `시작됨`이면 `실행 결과`까지 읽고 **세션 시작을 확인**했다고 보고한다. `확인 필요`이면 `실행 결과`의 원인을 함께 보고한다. 일정 시간 안에 상태가 바뀌지 않아도 요청 실패로 단정하지 않는다. 러너는 비동기이며 Mac이 꺼져 있거나 잠들면 나중에 처리할 수 있다.

## 결과

카드 URL, 제목, 프로젝트, 넛지헬스케어라면 저장소, `시작 단계`, `실행 에이전트`와 고른 근거(`claude=… codex=…`, 한쪽만 읽혔으면 추정), 확인된 `실행 상태`를 짧게 알린다. `요청됨`만 확인됐으면 "세션 시작은 아직 확인하지 못했습니다"라고 명확히 쓴다. 직접 Orca CLI를 중복 실행하거나, 다른 카드의 실행 상태를 변경하지 않는다.
