# 프로젝트 정체

> `/gs` 파이프라인의 `gs:planner`가 기획서를 쓰기 전에 읽는 문서입니다.
> **"이 아이디어를 웹 메모가 해야 하는가"** 를 판단하는 근거이며, 기능 명세가 아니라 방향을 적습니다.
> 규격은 [`plugins/gs/project-docs.md`](https://github.com/guesung/guesung) 의 "골격 — 정체"를 따릅니다.

## 정체

웹페이지를 읽는 흐름을 끊지 않고 그 자리에서 기록을 남기고, 남긴 기록을 웹에서 모아 보는 서비스.

크롬 확장(사이드 패널)이 기록하는 자리이고, 웹(`webmemo.xyz`)이 모아 보는 자리이며, iOS 앱이 밖에서 꺼내 보는 자리입니다. 세 진입점이 같은 메모 하나를 본다는 것이 이 프로젝트의 형태입니다.

## 페르소나

**아티클·유튜브를 읽고 보다가 "이건 남겨야겠다"가 자주 생기는 사람.** 만든 사람 본인이 1순위 사용자입니다.

이 사람이 지금 아쉬운 것:

- 기록하려면 노트 앱을 따로 열고 화면을 반으로 나눠야 한다
- 어떤 글을 읽고 쓴 메모인지 남기려고 제목과 URL을 매번 손으로 옮겨 적는다
- 그렇게 쌓인 메모가 노트 앱 어딘가에 흩어져 나중에 못 찾는다

즉 **메모를 못 써서가 아니라 메모까지 가는 마찰 때문에 안 쓰게 되는 사람**입니다. 기능을 늘리는 것보다 이 마찰을 줄이는 쪽이 항상 우선합니다.

## 톤·태도

**담백하고 친근한 존댓말.** 사용자를 가르치지 않고, 기능을 자랑하지 않습니다.

- UI 카피는 `~해요` 체. 명령형(`저장하십시오`)이나 광고체(`놀라운 요약 기능!`)를 쓰지 않습니다
- 실패했을 때 사용자를 탓하지 않고 다음에 뭘 하면 되는지 한 줄로 말합니다
- 기록의 주체는 사용자입니다. 제품이 대신 써주는 것처럼 말하지 않습니다

## 방향성

6~12개월 뒤:

- 메모를 **읽고 다시 꺼내 쓰는 쪽**이 지금보다 나아져 있는 것 — 카테고리·하이라이트·캘린더 뷰가 실제로 회고에 쓰일 만큼
- 크롬 확장에 갇히지 않은 것 — 웹·iOS 앱이 확장 없이도 각자 쓸 만한 상태
- 메모 공유(읽기 전용 링크) 수준의 밖으로 내보내기

지금 없어도 되는 것이라도 이 방향에 있으면 검토합니다.

## 하지 않을 것

- **범용 노트/위키 앱화** — 폴더 트리, 백링크, 리치 텍스트 에디터, 데이터베이스 뷰 같은 노션·옵시디언식 기능. 웹 메모는 "읽는 중에 남기는 기록"에 머뭅니다. 에디터가 깊어질수록 사이드 패널을 여는 이유가 사라집니다.
- **AI 자동 생성 콘텐츠 확대** — 요약(이미 있는 범위)을 넘어 메모 대필, 자동 태깅으로 사람 손을 대체하는 방향. 기록의 주체는 사용자라는 선을 지킵니다. AI는 읽기를 돕는 자리까지입니다.
- 위 둘에 걸리는 요청은 **사용자가 원해도 기획 단계에서 접습니다.** 접은 이유를 요청과 함께 남깁니다.

## 제약

- **퇴근 후·주말에만 작업한다.** 한 작업이 여러 날에 걸쳐 끊기므로, 작업 단위(=커밋·PR)가 작아야 하고 중간에 끊겨도 배포 가능한 상태여야 합니다.
- **서버 비용 최소화 — 무료 티어 안에서 해결한다.** Vercel·Supabase 무료 티어가 기준선입니다. 전용 서버, 상시 구동 워커, 유료 매니지드 큐를 전제한 설계는 채택하지 않습니다.
- **OpenAI API 토큰 비용이 실비로 나간다.** 요약·카테고리 추천은 본인 계정으로 과금됩니다. 호출 빈도·레이트리밋·캐시를 기능 설계의 기본값으로 함께 정합니다. 사용자 수에 비례해 비용이 선형으로 늘어나는 기능은 범위를 먼저 좁힙니다.
- 확장·앱은 심사를 거칩니다(크롬 웹스토어·App Store). 당일 롤아웃이 불가능하다는 전제로 릴리스를 계획합니다.
