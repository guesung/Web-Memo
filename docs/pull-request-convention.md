# Pull Request 컨벤션

이 문서는 Pull Request(PR) 네이밍 규칙을 설명합니다.

## PR 제목 형식

일반 커밋과 구분할 수 있도록, 모든 PR 제목은 첫 글자가 대문자인 접두사로 시작합니다.

### 접두사

1. `Feature`: 새로운 기능 추가
   - 예시: `Feature: 다크 모드 지원 추가`

2. `Fix`: 버그 수정
   - 예시: `Fix: 로그인 페이지 리다이렉트 이슈 해결`

3. `Chore`: 유지보수 작업
   - 예시: `Chore: 의존성 업데이트`

4. `Refactor`: 코드 구조 개선
   - 예시: `Refactor: 인증 플로우 개선`

## PR 템플릿

```markdown
## 설명
[변경 사항에 대한 상세 설명]

## 관련 이슈
[관련 이슈가 있다면 링크]

## 변경 유형
- [ ] Feature (새로운 기능)
- [ ] Fix (버그 수정)
- [ ] Chore (유지보수, 의존성)
- [ ] Refactor (코드 구조 개선)

## 테스트 방법
[수행한 테스트 내용을 작성]

## 스크린샷 (해당하는 경우)
[스크린샷 첨부]

## 체크리스트
- [ ] 이 프로젝트의 스타일 가이드를 따랐습니다
- [ ] 직접 작성한 코드를 셀프 리뷰했습니다
- [ ] 이해하기 어려운 부분에 주석을 작성했습니다
- [ ] 관련 문서를 함께 수정했습니다
- [ ] 새로운 경고(warning)가 발생하지 않습니다
```
