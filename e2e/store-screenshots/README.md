# 홍보 이미지 생성

`pnpm build:extension` 후 `pnpm -F e2e exec playwright test -c playwright.store.config.ts`를 실행합니다. 캡처 단계는 한국어판의 실제 메모 데이터와 영어판의 가상 데이터로 확장·웹 UI를 촬영합니다. 합성 단계는 같은 원본으로 다음 이미지를 만듭니다.

- `output/{ko,en}/screenshot-{1..5}.png`: 기존 크롬 웹스토어용 이미지(1280×800)
- `apps/web/public/images/webps/introduction/{ko,en}/{1..5}.webp`: 광고 헤드라인 없는 웹 이미지(1280×800)
- `apps/web/public/og-image.png`: 한국어 첫 장면의 공용 OG 이미지(1200×630)

## 장면

다섯 장 모두 같은 기사를 읽는 한 흐름입니다. 한국어는 실제 brunch 글, 영어는 `demoArticle.html`을 씁니다.

1. **칠하고 메모를 단다.** 기사 본문에 노란 하이라이트 하나와, 그 하이라이트를 눌러 연 편집 툴바(메모 칸이 열리고 메모가 채워진 상태). 사이드 패널은 흐리게 깔립니다.
2. **드래그하고 색을 고른다.** 1번 장의 하이라이트는 남아 있고, 다른 문장을 선택해 5색 버블이 뜬 상태. 사이드 패널은 1번 장처럼 흐립니다.
3. **Alt+S로 연다.** 하이라이트가 남은 기사 위에 확장 아이콘 원 강조와 키캡을 얹습니다.
4. **출처가 남는다.** 같은 기사 위에 사이드 패널의 메모 출처("메모 ↗" 줄과 글 제목 줄)를 확대한 카드를 얹습니다.
5. **한곳에서 모아 본다.** 웹 `/{lng}/highlights` 대시보드. 1번 장의 문장과 메모가 첫 카드 맨 위에 오고, 다른 페이지 카드가 이어집니다. 최종 렌더 크기인 1160×586, 픽셀 밀도 1로 촬영해 합성 과정에서 축소하지 않습니다.

하이라이트·메모·문장은 `demoData.ts`(영어)와 `realMemos.ts`(한국어)의 `highlightScene`에 있고, 목 저장소에 심어 확장이 실제로 복원·편집 툴바를 그리게 합니다(`demoRoutes.ts`). 찍히면 안 되는 상태(빈 상태, 스켈레톤, 저장 중·실패·로그인 요구 문구, 비활성 버블, 첫 선택 안내 말풍선)는 캡처 단계가 직접 확인해 하나라도 보이면 실패합니다. 5번 장은 칠한 문장 개수와 카드 개수도 확인합니다.

한국어판의 다른 페이지 하이라이트 문장은 해당 메모 본문에 적힌 말을 그대로 옮긴 시연용입니다. 공개 전에는 메모 제목·본문·출처와 로그인 상태를 직접 확인합니다.
